# VayyuEdge v0.2 Implementation Plan — Real Offline AI Pipeline

**Status**: In Progress  
**Objective**: Transition VayyuEdge from an interactive prototype to a genuinely working local-first English-to-Telugu speech intelligence application on personal laptops.

---

## 1. Repository & Runtime Audit Findings

### 1.1 Frontend (`apps/web`)
- **Technology**: React 18, Vite 5, TypeScript 5.4, Tailwind CSS 3.4.
- **Current Deployment**: Static GitHub Pages site at `https://ravivarmapatturi.github.io/vayyuedge/` (branch `gh-pages`).
- **Capability State**: Includes microphone capture (HTML5 `MediaRecorder`), audio upload, editable transcript UI, Telugu Unicode rendering, Web Speech API audio output, and client-side IndexedDB session storage.
- **Limitation Identified**: The hosted GitHub Pages site is purely static. It cannot execute local Python ML models without a local backend daemon running on the user's computer.

### 1.2 Backend (`services/api`)
- **Technology**: Python 3.12, FastAPI, Pydantic v2, Pytest 9.1.
- **Existing Architecture**: Clean modular monorepo with `BaseASRAdapter`, `BaseTranslationAdapter`, and `BaseTTSAdapter` abstract protocols.
- **Hardware & Library Baseline (Audited on Host)**:
  - OS: Linux 6.8.0 x86_64 (12 CPU cores, multi-threaded CPU vector instructions).
  - PyTorch: `2.5.1` (CPU inference supported).
  - OpenAI Whisper: Installed; model weights for `base.en` (~142MB) cached in `~/.cache/whisper/`.
  - Audio Toolchain: `/usr/bin/ffmpeg` installed and verified.
  - NLP Toolchain: `transformers` 5.16, `sentencepiece`, `sacremoses`, and `indic-nlp-library` installed.

## 2. Implementation Steps

```
┌────────────────────────────────────────────────────────┐
│                   VayyuEdge Web App                    │
│   (Auto-detects http://127.0.0.1:8000 on loopback)     │
└───────────────────────────┬────────────────────────────┘
                            │
               ┌────────────┴────────────┐
               │                         │
     [Backend Reachable]       [Backend Unreachable]
               │                         │
               ▼                         ▼
     Real Local Inference      Informative Local Setup Guide
     (Whisper + IndicTrans2)    + Verified Sample Evaluation
```

### Stage 1: Real Local Speech Recognition (ASR)
- Implement `WhisperLocalAdapter` supporting direct PyTorch CPU inference using OpenAI Whisper models (`tiny.en` / `base.en`) with fallback to `whisper.cpp` CLI.
- Implement robust audio normalization: invoke `ffmpeg` or `pydub` to convert incoming WAV, MP3, WebM, and OGG streams into standard 16kHz 16-bit mono PCM.
- Enforce strict limits: reject files >25MB or duration >180s.
- Safely clean up transient audio files immediately after inference.

### Stage 2: Real Local Translation (IndicTrans2)
- Implement `IndicTrans2LocalAdapter` targeting AI4Bharat IndicTrans2 (`eng_Latn` → `tel_Telu`).
- Support sentence-piece tokenization, sentence chunking, number preservation, and native Telugu script output.
- Keep translation completely independent from transcription so the user can review and edit text prior to model execution.

### Stage 3: Transparent TTS Strategy
- Audit browser speech synthesis engines: report whether a native Telugu voice (`te-IN`) is available.
- Define explicit voice policy: distinguish local neural voice, browser speech synthesis, and graceful fallback.
- Never falsely claim offline neural voice generation unless local voice weights are installed and tested.

### Stage 4: Enhanced Capabilities API (`GET /v1/capabilities`)
- Report dynamic availability of:
  - ASR adapter name, model size, and loaded status.
  - Translation adapter name, model variant, and loaded status.
  - TTS engine type (local neural vs browser synthesis vs disabled).
  - Host CPU core count, available RAM, and loopback mode.

### Stage 5: Frontend Integration & Transparency
- Connect frontend client to `http://127.0.0.1:8000`.
- Display a dynamic connection status indicator:
  - **Local Engine Connected**: Enables real microphone transcription and IndicTrans2 translation.
  - **Static / Standalone Mode**: Displays setup guidance to launch `services/api` on `127.0.0.1:8000` while offering verified sample presets for evaluation.

### Stage 6: Benchmarks, Privacy & Local Verification
- Update `scripts/benchmark.py` and `scripts/verify-local-mode.py` to evaluate real model latency and RAM consumption.
- Update `docs/privacy-and-threat-model.md` and `docs/benchmark-results.md`.
- Ensure all automated Pytest and Vitest tests pass.

### Stage 7: Stable Deployment
- Ensure GitHub Pages deployment (`gh-pages` branch) continues to serve the polished website with full documentation and local execution instructions.
